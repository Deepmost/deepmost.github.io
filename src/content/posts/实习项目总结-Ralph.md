# Ralph — 自主 AI Agent 循环执行器（个人项目 / Python）

## STAR（架构方向）

### S（Situation 背景）

AI 编码 Agent 单次会话上下文受限、无法长时程自主开发，一次性投喂大需求易跑偏、幻觉、无质量兜底；且 LLM 本质不可信其"自我约束"，无人值守下难以稳定产出成规模代码。

### T（Task 任务）

从架构层面设计一套任务文件驱动的多 Agent 自治系统，把大需求拆解为可独立执行、可验证、可治理的子任务流，并在代码层为不可信的 LLM 行为提供确定性兜底，实现"需求文档进、可用代码出"的无人值守闭环。

### A（Action 行动 — 架构设计与关键决策）

- **三 Agent 职责分离架构**：设计 Developer / Validator / PM 三个单一职责 Agent，通过独立的指令上下文（CLAUDE.md / VALIDATOR.md / PM.md）解耦，编排为"开发 → 逐条验收 → 治理沉淀"的自演进闭环，避免单 Agent 既当运动员又当裁判。
- **文件系统即状态机**：以带 YAML frontmatter 的 Markdown 任务文件作为可持久化队列，文件名序号定义执行顺序、id 作为稳定身份双维度解耦——PM 重排只改序号不动 id，Validator 始终按 id 定位任务，避免重排导致的状态错乱。全部状态落盘（state.json / progress.txt / adjustments.json），进程崩溃可恢复。
- **不信任 LLM 的防腐层（核心架构决策）**：基于"指令约束不可靠"的前提，在引擎层实现目录树快照对比 + 越界自动回滚机制——PM 运行前后各做一次快照，对任务正文篡改、受控字段（retryCount / blocked / validation_notes）改写、伪造完成、未经审计的删除重置、单轮超收敛阈值（净新增 > 3 / 重置 > 2）等 6 类越权行为做校验，越界即回滚至 PM 运行前状态。把"治理失控"从不可控风险转为确定性可回滚行为。
- **长时程稳定性设计**：流式解析子进程 stdout，构建三层超时保护（首字响应 120s / 持续静默 120s / 单任务总时长 30min）+ 验证失败自动回退重试（上限 5 次后标记 blocked 跳过），保障连续无人值守运行不卡死、不空转。
- **可扩展与可观测**：抽象 Agent 后端接口，兼容 Claude / Codex 双后端；docs/patterns-*.md 知识沉淀设 200 行预算告警控制各 Agent 上下文压力；配套独立 HTTP 监控面板（阶段徽标 / 任务状态 / 迭代进度 / 实时日志）与 adjustments.json 全量审计日志，实现全流程可观测、可审计。

### R（Result 结果）

- 交付可无人值守运行的自主开发系统，单次可自主执行 【__ 个】子任务、连续迭代 【__ 轮】，验证通过率 【__%】，全程无需人工介入。
- 900+ 行核心引擎覆盖调度、超时、防腐回滚、状态管理，将"LLM 治理失控"降为代码层确定性行为，长时程运行稳定性显著提升。
- 架构支持多平台（Windows / Linux / macOS）与多后端，防腐层与后端接口均可独立演进，具备良好扩展性。
