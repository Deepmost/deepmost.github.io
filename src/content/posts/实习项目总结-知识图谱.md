# 知识图谱功能（后端开发视角）

## Situation（背景）

在线学习平台需将课程内容结构化为"知识点—关系—学习资源"的图谱，支撑教师端图谱编辑与学生端可视化学习、按知识点追踪资源完成率。核心难点在于：课程知识点及关系是典型的图结构（多级父子、前置/后置依赖、跨节点关联），用关系型数据库表达多跳查询代价高；且大课程一键构建需一次性写入大量图节点与关系，同步执行会长时间阻塞、易触发图库事务超时回滚，用户连点还会产生重复数据。

## Task（任务）

作为后端开发，负责知识图谱服务的存储选型、图谱构建、查询接口与缓存设计，并解决大数据量构建下的性能、稳定性与并发问题。

## Action（行动）

### 存储与建模

- 选用 Neo4j 图数据库（Spring Data Neo4j + OGM），用 `@NodeEntity` 建模知识点节点 `Knowledge` 与资源节点 `ResourceNode`，通过 `@Query` 手写 Cypher 实现建图与查询。关系统一为 `:Knowledge` 类型并以 `type` 属性区分 5 种语义：子级(child)、前置(pre)、后置(next)、关联(relation)、关联资源(link)，支持 `[r:Knowledge*1..7]` 的多跳遍历与 `DETACH DELETE` 级联删子树，最大层级限制为 7 级。

### 三种图谱构建途径

- **一键生成**：读取课程章讲目录，用 `KnowledgeExtractor` 将目录树转为知识点节点、child 关系与资源关联；
- **AI 生成**：调用大模型网关（`ChatGptUtils`）按课程名生成"不少于 20 个节点"的图谱三元组 JSON，解析 nodes/relations 后推导 rootId、level 并入库；
- **按章节导入**：在导入基础上自动关联资源，并对视频节点解析"AI 智能总结"字幕，将每条字幕摘要裂变成按时间点关联的子知识点；字幕未生成时发 RocketMQ 异步任务交由课程空间生成，并用缓存标记防止重复投递。

### 性能与稳定性优化（核心贡献）

- **构建改为异步**：将接口从同步阻塞改造为"主线程完成 MySQL 查询 + 线程池异步执行 Neo4j 写入 + 立即返回 + 前端轮询进度"。这里踩到并解决了一个关键坑——异步线程不继承动态数据源上下文，因此把所有 MySQL 查询保留在主线程，异步任务只做纯图库与缓存操作。
- **生成状态机 + Redis 防重**：设计 running/success/failed 三态状态机写入 Redis，同一课程生成中直接拦截，杜绝用户连点、多标签页并发触发导致的重复节点；状态 key 设 30 分钟过期作为兜底，防止异常时状态残留导致课程再也无法生成。
- **分批写入**：针对单事务数据量过大导致图库批处理超时回滚的问题，按批大小 50 用 `CollUtil.split` 分批提交，且先写完全部节点再分批写关系（关系依赖节点已存在），保障千级以上节点的大课程稳定落库。

### 查询与缓存

- 设计多级 Redis 缓存（全部节点、一级知识点详情、节点子级、节点关系、标签、课程根节点反向索引等），2 小时 TTL；增删改节点/关系时按"课程→缓存 key 列表"反向索引精准失效，避免全量清缓存。
- 图谱查询在内存中把扁平的节点+关系组装成树形 DTO，用 `copyWithoutRelations()` 规避双向关系导致的 StackOverflowError，并做关联关系去重（正反向只计一次）。
- 学生端结合 `allowedPreview` 做闯关模式/顺序解锁的预览权限校验，并按知识点聚合关联资源的学习完成率。

## Result（结果）

以图数据库替代关系型建模，天然适配知识点的多跳关系查询；大课程图谱构建从同步阻塞的秒级等待变为异步秒级返回，用户无需等待即可继续操作、进度实时可见，大数据量场景下的构建体验与稳定性显著提升；同时通过状态机 + 分批写入，彻底消除了并发重复生成与图库超时回滚问题。
