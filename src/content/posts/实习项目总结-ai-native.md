# learnspace-ai-study 模块简介（STAR）

## Situation（背景）

`learnspace-ai-study-api` 与 `learnspace-ai-study-service` 构成 AI 原生学习平台的后端。传统在线学习平台是"人找内容"——学生自己看视频、做题、找章节，缺少陪伴感和个性化引导。我们要把它改造成"内容找人"：让 AI 智能体主导整个学习流程，学生只需对话，系统在背后自动推进学习进度。

## Task（目标）

从后端角度，核心任务是设计一套**多智能体协作 + 学习闭环驱动**的服务：既要让大模型的对话能力自然融入教学，又要保证学习进度、掌握度这些"状态"由后端可控、可持久化，不能全交给模型自由发挥。

## Action（做法）

围绕**智能体**落地了三个关键设计：

1. **三人格智能体体系（AgentConstants + ai-chat-prompts.yaml）**
   通过 Prompt 工程定义了导师"苏教授"（深度讲解）、学习伙伴"小伴"（情绪陪伴）、考官"严博士"（出题测验）三个 Agent，底层统一走 `AiModelRouter` 调用 CBB 大模型网关（默认 deepseek-v4-pro），支持 SSE 逐 token 流式、多模态识图和模型降级熔断。
2. **智能体自动委派（Handoff）状态机（HandoffParser / HandoffEvaluator）**
   每轮 AI 回复末尾输出结构化自评块，后端解析后由委派状态机决策是否切换人格——采用"连续 3 轮不匹配才切换 + 5 轮冷却"的宽松策略防止乒乓切换，状态持久化在 `learning_session`。这样智能体切换是后端可控的确定性逻辑，而非模型随机发挥。
3. **对话驱动学习闭环（ChatServiceImpl 为编排核心）**
   把一次对话解析成多路结构化信号：mastery 掌握度自评驱动 `MasteryServiceImpl`（增益算法 SSOT）推进知识点掌握度，handoff 驱动人格切换，GenUI 生成 quiz/code/video 交互卡片，followup 生成追问引导。配合 `LearningContextBuilder` 把学生当前知识点、掌握度、章节进度注入 Prompt，让讲解贴合真实学情。整条流程串起"引导测评 → 学习画像 → 学习路径 → 每日任务 → 对话/答题推进掌握度 → 章节推进"的闭环。

## Result（成效）

最终形成一个以智能体为入口、后端状态机为骨架的学习系统：学生在自然对话中被自动引导、自动测评、自动切换合适的"老师"，而掌握度推进、章节解锁、任务生成等关键状态全部由后端确定性控制、可持久化可追溯。AI 负责"表达和判断"，后端负责"状态和规则"，两者职责清晰分离。
