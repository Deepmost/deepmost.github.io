# 从一篇论文到 AI 推理时代的“Linux”：vLLM 如何穿越开源、创业与技术浪潮

当一个诞生于伯克利校园的研究项目，逐渐成为全球最重要的大模型推理基础设施之一，它接下来该怎么办？继续依靠学生和志愿者“用爱发电”，交给某一家大公司，还是成立一家公司，用商业力量反哺开源？

vLLM 核心维护者、Inferact 联合创始人兼首席科学家游凯超的答案是：开源项目需要基金会守住公共性，也需要一家由核心团队创办的公司，为它提供长期的人力、算力和组织能力。

这场近三小时的访谈，表面上讲的是 vLLM 从论文、社区到公司的成长史，底层讨论的却是三个更大的问题：在 AI 进入规模化时代后，什么样的研究才真正创造价值？AI 基础设施为什么正在成为模型能力的上限？当代码本身越来越廉价，开源社区又将靠什么维持生命力？

## 从追逐论文，转向追逐真实世界的影响

游凯超并不是从小参加信息学竞赛的“天才程序员”。他直到 2015 年才通过在线课程系统学习 Python。进入清华后，他享受的是学习本身：大量阅读、主动向老师请教、认真记录笔记，最终有 36 门课程获得 4.0，并拿到清华大学本科生特等奖学金。

但他并不愿意把这种经历概括成“卷”或“逆袭”。在他看来，高考分数只是进入大学的门票，进校后就该忘掉它；奖项也只是阶段性认可，不该成为衡量所有人的统一尺度。真正重要的问题始终是：自己想学什么、想解决什么问题。

早期的游凯超研究迁移学习、数据稀缺场景和大模型微调。随着研究深入，他逐渐看见了纯算法研究的局限。

一方面，AI 会议的投稿量增长远快于审稿社区的成长，评审越来越像抽奖；另一方面，许多算法工作只是让指标提高 1%—2%，而换一个更大、更好的基础模型，收益可能立刻超过一整年的算法优化。更关键的是，真正决定一个想法能否产生影响的，往往不是公式本身，而是有没有足够的数据、算力和系统能力把它扩展到真实规模。

这让他把评价工作的标准从“论文是否被接收”改成了“有没有人真正使用”。

系统研究给出的反馈更加直接：一个优化究竟加速了多少，用户是否降低了成本，原理能否被解释和复现，都可以客观验证。论文不再是目标，而只是系统产生影响后的副产品。

这也是他职业选择的转折点：比起在论文中争论一个想法是否足够新颖，他更愿意做一个真正有用、能够持续积累正反馈的系统。

## vLLM 的起点并不神秘，难的是把“简单想法”做成基础设施

2019 年，游凯超在伯克利 RISELab 暑期交流，第一次接触到机器学习系统研究，也结识了后来发起 vLLM 的李卓翰。导师 Ion Stoica 告诉他：“只要软件足够好，总会有人使用。”这句话在他心里埋下了一颗种子。

伯克利有一种独特的“重工业软件”传统。从 BSD、RISC-V 到 Spark、Ray，很多后来成为工业基础设施的项目，最初都只是学生在实验室中的研究课题。实验室、博士培养周期和产业需求一旦发生共振，一个校园原型就可能成长为改变行业的软件。

vLLM 也沿着这条路径诞生。

项目最初源于 2023 年的 PagedAttention 论文。它借鉴操作系统的虚拟内存分页思想，更高效地管理大模型自回归生成过程中的 KV Cache。这个想法并不以“复杂”取胜，论文投稿时甚至曾被评价为过于直接。它真正的价值在于出现得足够早，实验足够扎实，而且团队没有停在论文上，而是把原型开源并持续演进。

今天的 vLLM 早已不等于 PagedAttention。它吸收了连续批处理、投机解码、分布式推理和大量模型、硬件适配能力，成为屏蔽底层复杂性的通用推理引擎。用户只是在菜单中把模型从 Llama 换成 DeepSeek 或千问，背后的模型结构、并行方式、KV Cache 和硬件特性却可能完全不同。vLLM 的价值，就是把这些差异压在统一接口之下。

2024 年，游凯超再次前往伯克利交流，并成为 vLLM 较早全职投入的核心维护者之一。那一年，团队的主旋律是把研究原型重构成生产系统，从 V0 迈向 V1；2025 年，随着 DeepSeek R1 走红和中国开源模型集中爆发，主旋律又变成大规模部署与快速适配。游凯超回国后从零搭建中文社区，连接国内模型公司、芯片厂商和用户，vLLM 也由一个主要诞生、活跃于美国的项目，变成真正全球化的开源基础设施。

回顾这段经历，他给出的评价很克制：“不敢说做得多好，只能说撑过来了。”

## 为什么一个成功的开源项目，反而更需要成立公司

项目越成功，单靠开源社区就越难维持。

早期模型较小，一台机器就能完成很多测试，成员也可以靠兴趣参与。但当模型扩展到集群规模，问题完全变了：长期功能需要稳定的人力；新模型和新硬件发布前的适配涉及保密协议；大规模优化需要持续可用的集群；资金、设备采购和法律责任也都需要一个明确的主体。

开源社区不是法人，不能签 NDA；志愿贡献者来来去去，无法承诺季度目标；合作伙伴即使愿意提供算力，也很难把公司内部资源交给一群身份松散的个人。维护者常常要花一个月“借”来一批机器，又必须在资源随时可能被收回的压力下完成测试。

这就是 vLLM 团队最终创办 Inferact 的现实原因：不是为了把开源项目据为己有，而是因为没有公司，项目已经无法继续向前。

在公司成立之前，vLLM 已被捐赠给 PyTorch Foundation。基金会拥有项目商标，并从法律结构上保证它持续开源；Inferact 则成为技术维护和日常运营的核心力量，同时与 NVIDIA、AMD、Red Hat、云厂商及其他社区成员共同建设生态。

两者的分工非常清楚：基金会是防止项目闭源的“保险杠”，公司则是让项目持续加速的“发动机”。

成立公司的决定却并不轻松。核心成员都是技术背景，要突然学习融资、招聘、销售和组织管理；他们每个人也都拥有极具诱惑力的工作机会。据游凯超回忆，团队甚至在创业前夕收到过顶级大厂给四位创始人分别开出年薪 2000 万美元的邀请。

最终让他们站到一起的不是财务计算，而是一个问题：如果十年后自己赚了很多钱，但 vLLM 因无人长期维护而失败，会不会后悔？

他们的答案一致：会。

2026 年初，Inferact 获得 1.5 亿美元种子轮融资。公司的商业化仍围绕推理生态展开，包括托管推理服务、在客户云环境中部署，以及与战略客户共同优化。其基本原则不是出售工程师工时，而是按实际创造的价值收费：多产生了多少 token，替客户节省了多少计算成本。

这也揭示了开源商业化最健康的一种可能：公司获得收入的方式，与开源项目变得更强的方向一致。若商业客户的需求与社区目标冲突，团队现阶段的选择是不接这样的客户。

## AI 正在重写开源社区：代码越来越便宜，判断越来越昂贵

vLLM 一度成为 GitHub 上贡献者最活跃的项目之一，贡献者超过两千人。但生成式 AI 和 Coding Agent 的兴起，正在改变“贡献代码”这件事的含义。

当代码生成的成本急剧下降，维护者收到的未必是更多有效贡献，也可能是海量低质量 PR。访谈中提到，有培训机构让学员向热门项目提交无价值代码，以便在简历中写上“vLLM 贡献者”；也有自动化账号在十分钟内提交二十个 PR。开源社区过去默认参与者抱有善意，如今这个假设正在被打破。

代码变得廉价，并不意味着软件工程变得简单。恰恰相反，稀缺资源从“谁能写代码”转移成了“谁知道该写什么、为什么写，以及未来半年还要兼容什么”。

对 vLLM 这样的基础设施而言，维护者不能只修复眼前的问题，还要提前考虑三个月后发布的新模型、半年后出现的新硬件，以及今天的设计是否会变成明天的技术债。这些上下文、历史判断和路线取舍，目前仍无法完全交给 AI。

因此，未来的开源协作可能出现新的分工：用户更专注于提交高质量的 Bug 报告和需求反馈，核心维护者借助 AI 完成实现；项目治理则进一步集中于少数真正掌握上下文、能够判断方向的人和机构。AI 可以完成 90% 的路程，但最后决定系统形态的 10%，仍需要人的经验与洞察。

这也解释了为什么开源项目需要“仁慈的独裁者”。vLLM 有明确的分级治理结构：少数负责人在关键方向上拍板，核心维护者负责重要模块，Committer 承担日常开发，更广泛的贡献者参与社区。面对复杂系统，管理的核心不是把所有需求都接受下来，而是确定优先级，尤其是决定“不做什么”。例如，为避免系统复杂度失控，团队会删除不再适合主流大模型负载的 Beam Search 等功能，并把资源集中在主流模型、主流硬件和大规模部署上。

## 后摩尔定律时代，模型、系统、芯片和 Agent 必须一起设计

访谈中最有启发性的技术比喻，是把 AI 推理看成一套电力系统：硬件像风、水和阳光等自然资源，模型像发电机，推理引擎负责把算力转化成 token，再输送给用户。

在摩尔定律高速发展的年代，软件不用过多考虑硬件，两年后通用芯片自然会更快。如今，通用性能红利逐渐消失，芯片必须为特定负载设计。算法如果无法利用矩阵计算、低精度计算等专用能力，就等于没有抽中“硬件彩票”。Transformer 的成功，很大程度上就在于它适合 GPU 的大规模并行矩阵运算。

所以，模型结构决定了推理效率的上限。一个在硬件上极不友好的模型，系统工程师再努力也无法挽救；反过来，只从推理效率出发设计模型，也可能得到“发电很快但电没有用”的结果。算法、推理系统与芯片必须从各自为战转向联合设计。

DeepSeek 是访谈中被反复提及的正面案例。它不仅拥有顶级的 AI 基础设施团队，算法研究者也理解系统约束。从细粒度 MoE、专家并行到 FP8 训练和投机解码，很多模型创新都建立在高效实现和全栈控制能力之上。强大的系统能力扩大了算法团队可以探索的空间，算法设计又反过来推动系统走向极致。

联合设计还在继续向上延伸到 Agent 框架。Coding Agent 会反复调用模型，并携带大量历史上下文，推理引擎能否复用前缀缓存，直接影响成本和响应速度。如果框架频繁改写 System Prompt，把精确到秒的当前时间放在请求最前端，或者让所有定时任务在整点同时触发，就会导致缓存集体失效和流量尖峰。看似只是上层产品的一处小设计，最终却可能给底层集群制造巨大压力。

因此，下一阶段不只是模型与推理引擎协同，而是芯片、模型、推理系统和 Agent Harness 的四层协同。谁能让这四层真正共享信息、共同优化，谁才能在有限算力下产生更多有效 token。

## Token 像电，但又不是电

“Token 即电力”是理解 AI 基础设施的好比喻，却也容易让人忽略一个本质区别：电可以调制和标准化，token 不行。

电网可以把不同电厂产生的电统一成相同的电压和频率，所有家电按照标准接入。但 DeepSeek 的 token 无法转换成 Kimi 的 token，每个 token 都带着模型的能力、风格和训练数据烙印。同样数量的 token，价值可能完全不同。

这意味着未来的推理市场不会只是简单出售一种同质化商品。模型结构、推理引擎、Agent 框架和具体任务之间的适配，会共同决定 token 的成本与效用。vLLM 要做的，也不是制造某一种模型的 token，而是在两三百种模型结构、不同芯片和多样负载之间，提供尽可能通用、高效的运行底座。

这就是游凯超将 vLLM 类比为“AI 推理领域的 Linux”的原因。Linux 屏蔽了硬件差异，为无数软件提供通用运行环境；vLLM 则试图屏蔽模型和加速芯片的复杂性，让开放模型能够在各种基础设施上可靠运行。

## 三个值得记住的判断

访谈最后，游凯超给出了几个颇具争议、但逻辑一致的判断。

第一，AI 的上限越来越取决于系统，而不只是算法。FlashAttention 证明精确注意力也能高效计算，PagedAttention 与连续批处理降低了自回归生成的成本，投机解码又把逐 token 生成转化为成段验证。许多看似必须修改算法才能解决的问题，最终可能由系统创新重新定义。

第二，面向普通人的模型上下文可能会停留在百万 token 量级。更长的任务不一定需要无限扩展上下文，可以借助外部记忆、技能模块、工具和子 Agent 完成。这个判断是否成立仍有待时间验证，但它提醒行业：更大的数字未必自动等于更好的系统。

第三，开源模型最终可能胜出。模型与核电技术不同，它必须长期、大规模地向用户提供服务，而用户在使用过程中会积累足以训练和改进模型的数据。尤其在 Coding Agent 场景中，组织可能在较短时间内形成自己的数据飞轮。模型能力很难靠保密永久守住，真正的护城河将是持续、快速迭代的能力。

这个判断也与 vLLM 和 Inferact 的选择高度一致：他们赌的不是某一家模型公司永远领先，而是开放模型会持续繁荣，世界需要一个中立、通用、由开源生态共同建设的推理底座。

## 结语：选择有意义的事，然后长期把它做实

游凯超的经历并不是一条由奖项、论文和融资自然连接起来的“精英成功路径”。真正贯穿其中的，是评价标准的一次次变化：从分数转向学习，从论文转向用户，从个人机会转向项目的长期意义，从写出代码转向判断什么值得被写。

他给年轻研究者的建议也因此非常朴素：从第一性原理出发，先想清楚自己真正想要什么，再长期积累。行业越热、噪音越多，这种能力越稀缺。

vLLM 的故事同样说明，基础设施的价值往往不在于提出最炫目的概念，而在于把一个正确、甚至看起来简单的想法，持续做成所有人都能依赖的系统。论文可以是起点，开源可以聚集力量，商业化可以提供燃料，但决定项目能否走远的，仍是那群愿意对它长期负责的人。

如果十年后回头看，vLLM 是否真的成为 AI 推理时代的 Linux，答案尚未写定。但至少，它已经让一个更重要的问题变得清晰：在技术指数增长的时代，最稀缺的从来不只是聪明，而是方向感、责任感，以及把有意义的事情坚持做下去的能力。
